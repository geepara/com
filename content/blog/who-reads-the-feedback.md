title = "Who Reads The Feedback"
date = "2026-10-22"
description = "Feedback teaches the person who does the work. When AI does the work, it's worth asking when teaching a person through feedback still makes sense."
tags = ["ai", "learning", "work"]
+++

Feedback is a way of teaching. When someone corrects your work, the goal is that you do it better next time. That only pays off if you are the one doing the work next time.

AI is starting to break that assumption. More and more, a person directs the work and an agent does it. When you give that person feedback, they hand it to the agent. The agent fixes the problem, the person approves the fix, and nobody learns anything. The agent won't remember it, and the person never read it closely.

Software engineering is where this shows up first. When I review a pull request now, the author usually doesn't read my comments. They point their coding agent at them, the agent makes the changes, and the pull request gets merged. The next week another author's agent makes the same mistake and I write the same comment again. I've started putting that time into agent skills instead, which are written instructions the agent reads before it starts. A rule I add to a skill applies to every pull request after it.

The same thing will happen anywhere agents take over the doing. A lawyer marking up a junior associate's contract or a manager editing an analyst's model will watch their notes go straight to an agent.

So when does it still make sense to teach a person through feedback? I think it depends on what the feedback is about. Some feedback is about how to do the work, such as which component to reuse or how to word a clause. An agent can follow that kind of instruction as well as a person can, and once it's written down the agent follows it every time. That feedback should go to the agent.

Other feedback is about judgment. It covers what is worth doing, whether the result is actually good, and where the agent got something subtly wrong. The person still makes those calls, because they decide what to ask for and what to approve. That feedback is still worth giving to a person, and it only works if they read it themselves.

The catch is that people used to build judgment by doing the work and getting corrected on the details. If agents handle the details, people miss most of the practice that taught them what good looks like. I don't know yet what replaces that. The people who keep getting better may be the ones who still read their feedback instead of forwarding it.

For now I sort my feedback before I write it. If it is about how the work gets done, I write it for the agent. If it is about whether the work is right, I write it for the person.
